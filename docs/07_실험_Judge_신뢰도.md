# 07. 실험 — LLM Judge 신뢰도 (기획 1-7)

> 실험일: 2026-10-17 ~ 10-18 · 판정기: 로컬 27B (temperature 0) · 참조 라벨: **Claude Opus 5.5** (사람 라벨 아님)
> 산출물: `labels/` (기준 `RUBRIC.md`, 표본·라벨 `judge_v1/`, 재판정 결과 `rejudge_*/`) · 스크립트 `scripts/rejudge.py`, `scripts/judge_agreement.py`

## 1. 왜 했나

평가 파이프라인의 통과/실패 중 의미 판단(필수 내용 전달·금지 언행·목표 해결·근거 없는 말·실패 후 완료 발언)은 LLM Judge가 내린다.
판정기가 틀리면 에이전트 개선의 방향도 틀린다. 그동안 개별 오판 사례만 메모해 왔고(HANDOFF), 판정기 자체를 잰 적은 없었다.
두 가지를 잰다: **① 같은 입력이면 같은 판정을 내는가 (일관성)** · **② 판정이 맞는가 (참조 라벨과의 일치)**.

## 2. 방법

- **재료**: 저장된 실행 3개 — `runs/20261017_150104_C`(새 기준선 20통화) · `090326_C`(40통화) · `094427_C`(보류 세트 16통화) = **76통화, 판정 항목 501개**
  (통화 판정 236 + 근거 판정 265턴). 에이전트는 다시 돌리지 않고 `results.jsonl`의 통화 기록·trace로 판정 입력을 복원했다.
- **① 일관성**: 같은 입력으로 3회 재판정 + 질문 제시 순서를 섞어 1회.
- **② 일치도**: 50항목 표본에 참조 라벨.
  - 무작위 40: 항목 종류별 할당 × 판정기 판정(통과/실패) 층별 추출. 판정기 실패가 드물어(1.2%) 그냥 뽑으면 실패 쪽을 못 본다 →
    층마다 가중치(모집단 수/표본 수)를 남겨 전체 일치율은 모집단 비율로 되돌려 계산
  - 표적 10: 재판정에서 뒤집힌 항목 + 알려진 오판 후보(o1_h6·no_toss_card 근거 판정 턴). 오판 분석용 — 일치율에 넣지 않음
  - 라벨러: Opus 5.5 서브에이전트 3개가 나눠 붙임. 판정기 답을 보지 않음(표본 파일에 판정 결과·층 정보 없음).
    기준은 `labels/RUBRIC.md` — 판정기와 **같은 질문·같은 근거**, 애매하면 `confidence: low`

  재현율 9%는 판정기 통과 층(모집단이 큼)에서 참조 라벨 실패 1건(low)이 가중치로 커진 값.

## 7. 추가 실험 — 근거 판정의 지시문 민감도 (10/19)

### 7-1. 왜

`runs/20261018_190203_C`에서 「인증 완료됐어요」(앱 인증 `status: success` 직후의 말)가 근거 없음으로 판정됐다. 같은 문장·같은 도구 결과가 `064733`에선 근거 있음이었다. 판정기 입력에서 달라진 것은 워커 지시문(10/18 `card_loss.yaml`·`general.yaml` 수정)뿐. 기존 재판정 일관성(3회 뒤집힘 0)은 **같은 입력** 기준이라 이 흔들림을 못 잡는다.

근거 판정이 지시문 문구에 흔들리면, 지시문을 고칠 때마다 근거 점수가 같이 움직여 지시문 개선의 효과를 잴 수 없다. APO(지시문을 계속 바꾸는 작업) 전에 막아야 한다.

### 7-2. 방법 (`scripts/judge_instr_sensitivity.py`)

저장된 통화 80건(`064733`·`190203`, 291턴)의 근거 판정을 **발화·검색 문서·도구 결과는 그대로 두고 지시문만 바꿔** 다시 판정. 변형마다 2회.
- `old`: 커밋 995c0ab의 워커 지시문 (`064733` 당시, `labels/instructions_995c0ab.json`)
- `current`: 커밋 3cbc761의 워커 지시문 (`190203` 당시)
- `none`: 지시문 없음

판정기는 결정적이다 (모든 변형에서 같은 입력 2회 흔들림 0턴) → 변형 사이 뒤집힘은 전부 지시문 때문이다.

- **지시문은 근거로 필요하다**: 빼면 근거 없음이 5 → 32턴. 「지시문을 근거에서 뺀다」는 해법이 아니다
- **v3 수정** (`evaluation/scoring.py` `_GROUNDED`): 판정 범위를 사실 주장으로 한정하고 지시 준수는 보지 않는다고 명시, 질문·제안·진행 안내는 사실 주장이 아님, 처리 결과 보고는 그 도구의 성공 결과가 있으면 근거 있음. 입력 구성은 그대로
- **참조 라벨 대조** (`scripts/grounded_agreement.py`, judge_v1의 근거 항목 21건): 무작위 12건 일치 10 → 9, 표적 9건 9 → 9. 바뀐 1건(`150104 s1_b0_tracking_not_found r0 t2` 「판매자가 송장 번호를 미리 등록한 경우라…」 실패 → 통과)은 라벨 확신 낮음(low)이고 기존 미해결 경계 사례. 불일치 3건 모두 확신 낮음 라벨. 표본이 작아 방향 확인용

### 7-5. 근거 판정 v4 — 2단계 (10/21~24, `evaluation/grounding.py`)
