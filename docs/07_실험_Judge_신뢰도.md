# 07. 실험 — LLM Judge 신뢰도 (기획 1-7)

> 실험일: 2026-10-17 ~ 10-18 · 판정기: 로컬 27B (temperature 0) · 참조 라벨: **Claude Opus 5.5** (사람 라벨 아님)
> 산출물: `labels/` (기준 `RUBRIC.md`, 표본·라벨 `judge_v1/`, 재판정 결과 `rejudge_*/`) · 스크립트 `scripts/rejudge.py`, `scripts/judge_agreement.py`

## 1. 왜 했나

평가 파이프라인의 통과/실패 중 의미 판단(필수 내용 전달·금지 언행·목표 해결·근거 없는 말·실패 후 완료 발언)은 LLM Judge가 내린다.
판정기가 틀리면 에이전트 개선의 방향도 틀린다. 그동안 개별 오판 사례만 메모해 왔고(HANDOFF), 판정기 자체를 잰 적은 없었다.
두 가지를 잰다: **① 같은 입력이면 같은 판정을 내는가 (일관성)** · **② 판정이 맞는가 (참조 라벨과의 일치)**.

## 2. 방법

- **재료**: 저장된 실행 3개 — `runs/20261017_150104_C`(새 기준선 20통화) · `090326_C`(40통화) · `094427_C`(보류 세트 16통화) = **76통화, 판정 항목 501개**
  (통화 판정 236 + 근거 판정 265턴). 에이전트는 다시 돌리지 않고 `results.jsonl`의 통화 기록·trace로 판정 입력을 복원했다.
- **① 일관성**: 같은 입력으로 3회 재판정 + 질문 제시 순서를 섞어 1회.
- **② 일치도**: 50항목 표본에 참조 라벨.
  - 무작위 40: 항목 종류별 할당 × 판정기 판정(통과/실패) 층별 추출. 판정기 실패가 드물어(1.2%) 그냥 뽑으면 실패 쪽을 못 본다 →
    층마다 가중치(모집단 수/표본 수)를 남겨 전체 일치율은 모집단 비율로 되돌려 계산
  - 표적 10: 재판정에서 뒤집힌 항목 + 알려진 오판 후보(o1_h6·no_toss_card 근거 판정 턴). 오판 분석용 — 일치율에 넣지 않음
  - 라벨러: Opus 5.5 서브에이전트 3개가 나눠 붙임. 판정기 답을 보지 않음(표본 파일에 판정 결과·층 정보 없음).
    기준은 `labels/RUBRIC.md` — 판정기와 **같은 질문·같은 근거**, 애매하면 `confidence: low`

## 4. 발견과 수정

| | 발견 | 수정 | 결과 |
|---|---|---|---|
| (a) | **턴 번호 어긋남 (버그)**: 인바운드는 인사가 통화 기록 `상담원(1)`이라 trace 턴 N의 응답이 `상담원(N+1)`인데, false_completion 질문은 「N번째 상담원 발화」로 물음 → 판정기·라벨러 모두 실패 턴의 **앞 발화**를 봄. 라벨러 3명이 각자 지적해서 찾음 | 번호 대신 해당 발화 문장을 질문에 인용 | 유지 |
| (b) | **되받기 오판**: 근거 판정 규칙은 「고객 말 되풀이는 사실 주장 아님」인데 근거 판정 프롬프트에 **고객 발화가 아예 없음** (`tracking_not_found` 「15일에 안 오면 다시 연락 주세요」) | 그 턴까지의 고객 발화를 프롬프트에 추가 | **되돌림** — 노린 1건은 고쳤지만 판정기가 관대해져 근거 판정 실패가 265턴 중 **0건**. 참조 라벨이 실패로 본 2건(원인 단정, 「삼성카드에서 바로 처리해 드릴 거예요」)도 통과시킴. 실패를 못 잡는 판정기는 쓸 수 없음 |
| (c) | **목표 판정이 설계 의도와 충돌**: `h8` — 타사 카드라 처리 불가 이유·다음 행동을 안내했는데 「현대카드 고객센터 번호를 안 줬다」로 실패. 근거 없는 번호를 지어내지 않는 것이 설계 의도 | 목표 판정 질문에 「근거 없는 정보를 주지 않은 것은 실패가 아니며, 확인할 곳을 안내했으면 다음 행동 안내로 본다」 추가 | 유지 |

그 밖에 확인한 것:
- **false_completion 질문 대상 대부분이 정상 흐름**: 「실행이 실패·차단된 턴」으로 잡히는 21턴 중 **18턴이 고객 확인 대기**(`confirmation_required`) 게이트였고(나머지 3턴은 도구 실패),
  발화는 「진행할까요?」 같은 확인 질문 → 항목이 거의 늘 쉽게 통과한다. 진짜 실행 실패(백엔드 오류 등)만 대상으로 좁힐지 검토 거리
- 최종 판정기에 남은 불일치 3건은 모두 참조 라벨 확신 낮음:
  `s4_b0_friend` 「10만 원이 더 간 거네요」(실제 차액 10만 8천 원 — 판정기 통과) · `tracking_not_found` 되받기(판정기 실패, (b) 미해결) ·
  `h1_two_cards` 목표(표적, 질문 순서에도 흔들린 경계 사례 — 최종에서 판정기 실패로 바뀜)

## 5. 한계

- **참조 라벨은 Opus 5.5이고 사람 라벨이 아니다.** 판정기와 참조 라벨이 **같이 틀린** 경우는 걸러지지 않는다.
- 판정기 실패가 501항목 중 6개뿐이라 **실패 탐지 정밀도·재현율(최종 75% / 9%)과 κ는 표본이 작아 크게 흔들린다** — 방향 확인용으로만 쓴다.
  재현율 9%는 판정기 통과 층(모집단이 큼)에서 참조 라벨 실패 1건(low)이 가중치로 커진 값.
- 표본 40건. 최종의 근거 판정은 다시 돌리지 않고 v1 판정을 썼다 — 근거 판정 프롬프트가 v1과 같고, v1에서 3회 재판정 뒤집힘 0건이라 같은 결과로 봄 (`labels/rejudge_final_merged/README.md`).
- (a)·(c)는 저장된 실행의 채점 결과(`results.jsonl`)를 바꾸지 않았다. 이후 실행부터 적용된다.

## 6. 재현

```bash
python scripts/rejudge.py runs/20261017_150104_C runs/20261017_090326_C runs/20261017_094427_C --k 3 --shuffle 1
python scripts/judge_agreement.py sample labels/rejudge_<시각> --out labels/judge_v1 --include ...   # 표본 (seed 0)
python scripts/judge_agreement.py score  labels/rejudge_final_merged --out labels/judge_v1 --k 1 --labels labels_v2.jsonl
```

라벨 파일: `labels.jsonl`(v1 질문 기준) · `labels_v2.jsonl`(false_completion 4건을 고친 질문으로 다시 붙임, 나머지 동일)
