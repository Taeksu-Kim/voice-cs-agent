# 09. 오동작 가드레일

> 상태: 2026-10-19 후보 정리 + 1차 적용 (G1·G2). 외부 위협(사기·민감정보)이 아니라 **에이전트 자신의 오동작**을 하네스에서 막는 장치.
> 원칙: 표현 목록으로 이상하게 막지 않는다. **실제로 일어났고, 판정 기준이 논리적으로 분명하고, 막았을 때 부작용이 작은 것**만 넣는다.
> 나머지는 발생 건수와 함께 여기 남겨 두고, 다시 나타나면 그때 넣는다.

## 3. 적용 내용

**G1 시각 없는 예약 거절** (`domain/app.py` `/notify/callback`)
- `when`이 비었거나 「unknown·미정·모름」처럼 「시각 없음」을 뜻하는 값이면 `WHEN_REQUIRED`로 거절. 오류 문구가 다음 행동(고객에게 묻고 답을 기다리기)을 알려 준다
- 도메인 API에 둔 이유: 「예약에는 시각이 있어야 한다」는 업무 규칙이다 (`docs/08` 6-3 검증 계층). 시각 표현이 맞는지(「오후 4시 이후」)는 판단하지 않는다 — 표현 목록으로 막지 않는다

**G2 지금 확인하겠다고 하고 끝내는 턴 되돌리기** (`loop.py`)
- 조건: 이 스텝에 도구가 없고, 말의 **마지막 문장**이 「확인해 볼게요·확인해 드릴게요·알아봐 드릴게요·조회해 볼게요」로 끝나며 조건절(「~면」)이 없다
  - 「확인해 볼게요. … 확인됐어요」처럼 약속 뒤에 답이 있으면 해당 없음
  - 「직접 전화 주시면 확인해 드릴게요」(나중 일)는 해당 없음
- 동작: 턴을 끝내지 않고 한 번만 되돌려 보낸다 — 도구를 부르거나, 확인할 수 없는 일이면 그렇다고 말하게. 이미 나간 말은 그대로 둔다 (고객은 「확인해 볼게요」 다음에 결과를 듣는다)
- 기록: trace `promise_nudge`

## 7. G7 출력 순서 도구 → 말, 막힐 스텝의 말은 내보내지 않기 (10/19)

- `WORKER_SCHEMA`·`prompts.SYSTEM` [출력 형식]의 키 순서: `intent, pending_answer, slots, tool, say, confirm` (전에는 say가 tool 앞)
- say 첫 조각이 나올 때 이미 생성된 tool로 `_would_block`을 본다 — `_run_tool`과 같은 검사(허용 도구·인자 근거·업무 규칙·게이트)를 부작용 없이.
  막힐 것으로 보이면 그 스텝의 말을 붙잡는다
  - 실제로 막혔으면 버린다 (trace `unheard_drop`, `blocked`: confirmation·precheck·not_allowed 등). 고객은 다음 스텝의 질문만 듣는다
  - 예측과 달리 실행됐거나(이번 스텝의 동의가 반영돼 통과 등) 질문으로 남으면(`question_hold`) 늦게라도 내보낸다 (`spoken` `late: true`)
  - 실행 중 실패(백엔드 장애)는 미리 알 수 없다 — 그 말은 들린다 (G3로 기록에는 남는다)
- 같이 고친 것: 도구를 시도하다 한마디도 못 한 턴은 「잘 못 들었어요」 대신 「확인하는 중에 문제가 생겼어요」 (고객 탓이 아니다)
- 테스트 스크립트 출력도 실제 순서(tool → say)로 바꿈 — 예전 순서로는 새 판정 경로가 테스트에서 돌지 않았다
- 확인: 테스트 140 통과, 전체 회귀 → 8절
