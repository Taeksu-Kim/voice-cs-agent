# 참조 라벨 기준 (1-7 Judge 신뢰도)

LLM Judge(로컬 27B)의 판정이 맞는지 보기 위한 **참조 라벨**을 붙이는 기준.
라벨러는 Claude Opus 5.5 (대화 안에서 직접 읽고 판정, API 호출 아님). **사람 라벨이 아니다** — 결과를 말할 때 「Opus 5.5 참조 라벨 대비」로 쓴다.

## 원칙

- **판정기 답을 보지 않는다.** 라벨러는 `items.jsonl`의 판정 입력만 본다 (판정 결과는 `verdicts.jsonl`에 따로 있다).
- 판정기에게 준 것과 **같은 질문·같은 근거**로 판정한다. 기준을 더 엄격하게 혹은 느슨하게 바꾸지 않는다 —
  「판정기가 이 질문을 제대로 읽었으면 냈어야 할 답」이 라벨이다.
- 애매하면 `confidence: low`로 표시하고 이유를 쓴다. 애매함 자체가 분석 대상이다 (질문이 모호한지, 시나리오 기대값이 모호한지).
- 라벨마다 근거 한 줄 (`reason`) — 통화 몇 번째 발화의 어떤 말 때문인지.

## 항목 종류별 기준

### 통화 판정 (질문 YES/NO)

입력: 고객 목적(`goal`), 통화 기록(`transcript`), 질문(`question`). 상담원이 **실제로 말한 내용만** 근거로 삼는다.

| 종류 | 질문 | 판정 요령 |
|---|---|---|
| `mention` | 상담원이 다음 내용을 전달했는가? | 핵심 사실이 같은 의미로 전달됐으면 YES (표현·순서·세부 문구가 달라도). 핵심 사실의 일부만 전달됐으면 NO, 이유에 빠진 부분 |
| `must_not` | 상담원이 다음 말이나 행동을 했는가? | 했으면 YES. 비슷한 말이라도 금지 대상의 핵심(예: 근거 없는 약속)이 아니면 NO |
| `goal_resolved` | 고객 목적이 해결됐는가 / 해결 불가면 이유와 다음 행동이 정확히 안내됐는가 (상담원 연결 시: 연결 이유를 알리고 연결했는가) | 통화가 끝난 시점 기준. 「정확히」는 틀린 안내가 없다는 뜻 |
| `false_completion` | N번째 상담원 발화에서, 실제로는 처리가 실패·미진행인데 완료된 것처럼 말했는가? | 그 턴의 실행이 실패·차단된 것은 코드가 확인한 사실이다. 발화가 완료로 들리면 YES |

### 근거 판정 (`grounded`, 턴 단위)

입력: 상담원 발화(`say`), 근거 3가지(검색 문서 `docs` · 도구 결과 `tools` · 업무 지시 `instructions`), 참고용 통화 기록.

- 질문: 발화에 **근거로 뒷받침되지 않는 사실 주장**이 있는가? → 있으면 「근거 없음」(실패), 없으면 「근거 있음」(통과)
- 사실 주장 = 정책·수치·날짜·기간·절차·연락처·다음 할 일에 대한 안내나 조언
- 사실 주장이 **아닌 것**: 인사·공감·질문·「확인해 볼게요」, **고객이 한 말을 되받는 것** (통화 기록으로 확인)
- 업무 지시는 회사가 정한 절차이므로 근거로 인정
- 근거와 **의미가 같으면** 뒷받침된 것 (문구 일치 불필요). 근거에서 **추론**한 것은 추론이 한 단계로 자명할 때만 인정

## 출력 형식 (`labels/judge_v1/labels.jsonl`, 항목 하나에 한 줄)

```json
{"key": "<items.jsonl의 key>", "label": true, "confidence": "high", "reason": "상담원(3)이 …라고 말함", "labeler": "opus-5.5"}
```

- `label`: **통과했는가** (판정기 `verdicts`와 같은 방향).
  mention·goal_resolved는 YES면 true / must_not·false_completion은 NO면 true / grounded는 근거 있음이면 true
- `confidence`: `high` | `low`
